# 论文一致性核心严谨性改造设计

## 设计目的

本次改造用于提高论文第 3 章算法实现的严谨性，但不增加论文之外的优化目标、状态变量或学习机制。项目仍严格保持两个阶段：先通过算法 3.1 生成 `List_seq`，再通过算法 3.2 的 PER-DDPG 为每个任务选择执行节点和 CPU 资源比例。

本次改造允许已有 Actor/Critic 检查点失效。新检查点将记录模型结构版本，使不兼容模型在加载时给出明确错误，而不是产生难以理解的张量维度异常。

## 改造范围

本次实现包括：

- 节点选择动作只包含论文允许的执行位置；
- 保持论文中的状态、动作、奖励、PER 和 LD-Noise 定义；
- 一致地执行论文中的最小 CPU 和并发 CPU 约束；
- 使生成 DAG 的实际边密度与配置值一致；
- 允许 DAG 存在多个入口任务；
- 使用多个训练随机种子，使算法对比结果可审计；
- 增加 PER 和 LD-Noise 消融实验，但不改变 PER-DDPG 本身；
- 保留现有 Web 入口和主要响应字段。

本次不增加能耗、费用、内存、GPU、存储、节点故障、移动性、带宽竞争、多 DAG、公平性和截止时间惩罚，也不使用图神经网络、Gumbel-Softmax、参数化动作算法或排序与卸载联合优化器替换论文算法。

## 论文算法一致性

### 算法 3.1

算法 3.1 继续作为独立且确定性的预处理阶段，按照论文计算：

- 根据公式 3.18 计算本地、最近雾节点和云节点的平均处理时间；
- 根据公式 3.19 计算静态向上优先级 `rank_i`；
- 根据公式 3.20 和 3.21 计算动态紧迫性；
- 根据公式 3.22 计算综合调度优先级 `W_i`；
- 生成满足拓扑约束的线性序列 `List_seq`。

排序规则不增加节点负载、能耗、可靠性或学习得分。虚拟时间 `T_now` 仍按照论文描述，使用已选任务的平均处理时间推进。

### 算法 3.2 的状态

观测状态严格保持公式 3.23：

```text
s_t = {I_t, CR_t, R_t}
```

`I_t` 只包含任务数据量、计算密度、最小 CPU 和最早就绪时间四个值。`CR_t` 包含云节点、所有雾节点和所有边缘节点的剩余 CPU。`R_t` 包含当前任务到各雾节点的上行传输速率。固定 WAN 速率继续作为环境配置，不重复放入 `R_t`。

状态中不增加 `rank`、紧迫性、序列进度、队列长度、截止时间松弛量、前驱位置或历史 makespan。

### 算法 3.2 的动作

动作严格保持公式 3.24：

```text
a_t = {A_t, F_t}
```

对于当前任务 `I_i`，可行节点列表始终按以下顺序排列：

```text
[cloud_0, fog_1, ..., fog_M, edge_i]
```

`A_t` 是长度为 `M+2` 的 Softmax 向量，`F_t` 是一个位于 `(0,1]` 的 Sigmoid 输出。因此 Actor 总动作维度为 `M+3`，不随任务数量或边缘设备数量改变。环境选择 Softmax 最大分量，并通过当前任务的可行节点列表映射到真实节点。Actor 不再输出其他任务所属边缘设备的无效概率。

DQN 基线使用相同的 `M+2` 个节点选项及原有离散资源档位。FLE 和 RO 也复用相同的可行节点定义。

### CPU 资源约束

`F_t` 表示目标节点剩余 CPU 的请求比例。在满足依赖关系和传输条件的最早到达时刻，调度器计算：

```text
requested_cpu = available_cpu * F_t
allocated_cpu = max(task.min_cpu, requested_cpu)
```

实际分配不能超过整个执行区间内的可用 CPU。如果当前可用资源小于 `task.min_cpu`，任务等待资源释放，直到出现满足条件的执行区间。如果节点物理容量本身小于 `task.min_cpu`，等待也无法满足约束，调度器应抛出说明清楚的错误。

由于公式 3.16 和 3.17 是硬约束，环境转换仍使用约束后的实际资源。经验池保存 Actor 原始动作，步骤审计记录同时提供 `requested_resource_ratio`、`requested_cpu`、`allocated_cpu` 和 `effective_resource_ratio`，从而显示动作经过约束后的实际执行结果，但不改变论文的动作定义。

### 奖励、PER 与探索机制

每个决策步的奖励保持公式 3.25：

```text
R_t = -max(FT_i)
```

不引入增量 makespan 奖励或额外惩罚。PER 优先级保持为 `(|TD error| + epsilon) ** alpha`。论文一致性默认值保持 `alpha=1`，并通过 `beta=0` 关闭重要性采样修正。LD-Noise 继续采用独立高斯动作噪声，并在完整训练周期内线性衰减。

## DAG 生成规则

对于 `N` 个任务，可选无环边为全部满足 `i<j` 的有序任务对 `(i,j)`，最大边数为 `N*(N-1)/2`。配置项 `dag_edge_prob` 解释为目标边密度，生成器从候选边中无放回抽取：

```text
round(dag_edge_prob * N * (N - 1) / 2)
```

条边。抽取后不再强制给无前驱任务补充父节点。这样既能保证无环，也允许多个入口和出口任务，并使实际边密度与目标值的误差不超过一条边的舍入误差。

每条选中边继续按照现有论文一致性范围生成中间数据量。算法 3.1 只有在某个后继任务的全部前驱都进入 `List_seq` 后，才能将其加入就绪集合。

配置校验拒绝 `[0,1]` 范围外的 `dag_edge_prob`，并拒绝小于 1 的任务数量。

## 实验设计

论文中的 FLE、RO、DDPG、DQN 和 PER-DDPG 对比算法全部保留。实验程序额外支持以下诊断性消融组合：

- `DDPG`：均匀经验回放和固定高斯噪声；
- `DDPG+PER`：优先经验回放和固定高斯噪声；
- `DDPG+LD`：均匀经验回放和 LD-Noise；
- `PER-DDPG`：优先经验回放和 LD-Noise。

这些组合用于分别判断 PER 与 LD-Noise 的贡献，不改变论文命名的 PER-DDPG 配置。

命令行保留 `--seed` 作为可选的单种子覆盖参数，并新增逗号分隔的 `--seeds`，默认值为 `42,43,44,45,46`。显式提供 `--seed` 时只运行该种子。每种算法使用完全相同的训练种子和评估种子。

实验结果保留逐回合样本，并新增：

- 独立训练种子数量；
- 各种子平均 makespan 的总体均值；
- 各种子平均 makespan 的标准差；
- 每个种子的训练与评估结果；
- 边密度实验中的配置密度和实际测量密度；
- 明确说明结果由本项目本地生成，不是论文原始数据。

`smoke` 模式只用于验证流程，不得标注为论文性能复现。`full` 模式继续用于论文规模的研究对比。

## 模型与 API 兼容性

新模型结构版本为 `2`。保存检查点时，除网络权重外还需写入元数据文件，记录结构版本、状态维度、动作维度、雾节点数量和任务数量。加载权重前先校验这些字段。缺少元数据或结构不兼容的旧检查点应被拒绝，并提示重新训练。

现有 Web 路由和主要字段继续保留。决策记录保留 `resource_ratio`，并将其作为 `requested_resource_ratio` 的兼容别名，同时增加请求比例、实际比例和实际 CPU 字段。前端根据紧凑的可行节点动作列表显示节点标签。

## 异常处理

环境校验动作长度必须为 `M+3`，且全部数值有限。探索噪声加入后重新归一化节点概率；如果节点概率全部为 0，则退化为 `M+2` 个可行节点上的均匀分布。`F_t` 使用现有下限裁剪到 `(0,1]`。

当所有物理节点容量都不能满足任务最小 CPU 时，调度器抛出描述清楚的异常。PER 继续拒绝非有限的总优先级。实验失败时先记录对应的随机种子和算法名称，再向上抛出异常，以便复现。

## 测试与验收

每项生产代码修改都先编写测试，并确认测试因旧行为不符合新规格而失败，再进行实现。

论文一致性测试覆盖：

- 生成边数与配置密度的误差不超过一条边的舍入误差；
- 生成 DAG 无环，并能产生多入口任务；
- `List_seq` 中每个前驱都严格位于后继之前；
- 在手工 DAG 上验证公式 3.18 至 3.22；
- 状态字段和维度严格符合公式 3.23；
- 动作维度为 `M+3`，且只能映射到云、雾或当前任务本地节点；
- 请求和实际 CPU 满足公式 3.16 与 3.17；
- 当前 CPU 不足时等待执行，不发生资源超配；
- 每一步奖励等于当前最大完成时刻的负值；
- PER 优先级和 LD-Noise 衰减符合论文公式；
- 模型元数据能够明确拒绝不兼容检查点；
- 四种消融组合使用正确的经验回放与噪声机制；
- 多种子 JSON 和 CSV 包含种子级结果及汇总统计；
- 现有 Web 路由和兼容字段继续可用。

完成条件为现有测试和新增论文一致性测试全部通过，并使用至少两个随机种子完成一次 smoke 对比。Smoke 输出需要具备有限数值、正确来源说明、预期算法名称和完整种子统计，但不要求算法性能满足特定排序。
